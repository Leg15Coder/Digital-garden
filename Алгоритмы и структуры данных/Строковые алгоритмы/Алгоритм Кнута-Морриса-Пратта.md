### Цель и проблематизация

Задача точного поиска подстроки (паттерна) $P$ ($|P|=m$) в тексте $T$ ($|T|=n$) - одна из базовых задач строковых алгоритмов. Наивный алгоритм проверяет сдвиги $P$ относительно $T$ и в худшем случае требует $O(n \cdot m)$ операций сравнения символов. 

Основной недостаток наивного подхода заключается в полном "забывании" информации о совпавших символах при возникновении расхождения. Для исключения повторных проверок необходима структура данных, позволяющая мгновенно определять максимальный сдвиг паттерна, сохраняющий совпадение уже проверенного контекста. Такой структурой является префикс-функция.

## Алгоритм Кнута-Морриса-Пратта

> [!important] Цель
> Поиск всех точных вхождений образца (паттерна) $P$ длины $m$ в текст $T$ длины $n$ за линейное время $O(n + m)$ без возвратов по тексту $T$.

### Алгоритм

1) Сформировать объединённую строку $S = \overline{P\#T}$, где $\#$ - специальный символ, не принадлежащий алфавиту $P$ и $T$ ($\# \notin \Sigma_P \cup \Sigma_T$).
2) Вычислить [[Префикс-функция|префикс-функцию]] $\pi$ для строки $S$ длины $m + 1 + n$.
3) Пройти по элементам массива $\pi[i]$ для позиций $i \in \overline{m+1, m+n}$:
	3.1) Если $\pi[i] == m$, зафиксировать вхождение образца $P$ в текст $T$.
	3.2) Рассчитать начальный индекс вхождения в тексте $T$: $\text{index}_T = i - 2m$.
4) Вернуть список всех найденных начальных индексов вхождений.

```python
def kmp_search(pattern: str, text: str) -> list[int]:
    concat_str = pattern + "#" + text
    pi = prefix_function(concat_str)
    m = len(pattern)
    occurrences = []
    
    for i in range(m + 1, len(concat_str)):
        if pi[i] == m:
            occurrences.append(i - 2 * m)
            
    return occurrences

```

#### Асимптотика

* **Временная сложность:**
1. Формирование строки $S = \overline{P\#T}$ длины $m + 1 + n$ занимает $O(n + m)$ времени.
2. Вычисление префикс-функции $\pi$ для строки $S$ с помощью линейного алгоритма требует $O(|S|) = O(n + m)$ операций.
3. Проход по массиву $\pi$ и фильтрация результатов занимает $O(n)$ времени.
4. Итоговая временная сложность составляет: $T(n, m) = O(n + m)$.


* **Пространственная сложность:** Память для хранения массива $\pi$ и строки $S$ составляет $O(n + m)$. При онлайн-обработке текста $T$ объём памяти сокращается до $O(m)$ за счёт хранения префикс-функции только для шаблона $P$ и поддержания текущего состояния автомата.

#### Корректность

Доказательство корректности основывается на свойствах разделителя $\#$ и префикс-функции:

1. **Ограничение на значения $\pi[i]$:**
Так как символ $\# \notin \Sigma_P \cup \Sigma_T$, он не равен ни одному символу из $P$ и $T$. Из этого следует, что ни один супрефикс не может включать в себя символ $\#$ в качестве внутреннего символа.

$$\forall i \in \overline{0, |S|-1} \ : \ \pi[i] \le m$$


2. **Критерий вхождения:**
Равенство $\pi[i] = m$ равносильно тому, что подстрока $S[:i+1]$ имеет собственный супрефикс длины $m$.
По определению префикс-функции данный супрефикс совпадает с префиксом строки $S[:m]$, то есть с шаблоном $P$.

$$\pi[i] = m \iff S[i-m+1:i+1] = P$$


3. **Расчёт индекса в тексте $T$:**
Супрефикс длины $m$, заканчивающийся в позиции $i$ строки $S$, расположен в части текста $T$.
Поскольку префикс $\overline{P\#}$ имеет длину $m + 1$, позиция $i$ в строке $S$ соответствует позиции $i - (m + 1)$ в тексте $T$. Начальный индекс вхождения $P$ в текст $T$ равен:$$\text{index}_T = (i - m - 1) - m + 1 = i - 2m$$

#### Пример применения

Пусть $P = \text{"aba"}$ ($m = 3$), $T = \text{"ababa"}$ ($n = 5$).

1. Формирование объединённой строки:$$S = \text{"aba\#ababa"}, \quad |S| = 9$$
2. Вычисление префикс-функции $\pi$ для строки $S$:$$\pi = [0, 0, 1, 0, 1, 2, 3, 2, 3]$$
3. Проверка значений $\pi[i] == m$ ($m = 3$):
* При $i = 6$: $\pi[6] = 3 \implies \text{index}_T = 6 - 2 \cdot 3 = 0$. (Вхождение $T[0:3] = \text{"aba"}$)
* При $i = 8$: $\pi[8] = 3 \implies \text{index}_T = 8 - 2 \cdot 3 = 2$. (Вхождение $T[2:5] = \text{"aba"}$)

1. **Итог**: найдены вхождения на индексах $[0, 2]$.

> [!SUCCESS] Достоинства КМП
> * Строгая детерминированная временная сложность $O(n + m)$ без риска наихудших случаев.
> * Возможность работы в онлайн-режиме (потоковая обработка текста без загрузки всего файла в память).
> * Отсутствие риска коллизий в отличие от хеширования.
