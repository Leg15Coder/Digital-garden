Пусть дана строка $S = s_0 s_1 \dots s_{n-1}$ длины $n$ над алфавитом $\Sigma$. Обозначим $S[i:]$ суффикс строки $S$, начинающийся с индекса $i$.

==Опр.== **Z-функция** - массив $z$ длины $n$, где $z[i]$ равен длине наибольшего общего префикса (LCP) всей строки $S$ и её суффикса $S[i:]$.

Формально для каждого $i \in \overline{1, n-1}$ :$$z[i] = \max\limits_{k \in \overline{0, n-i}} \{ k \mid S[:k] = S[i:i+k] \}$$По соглашению полагается $z[0] = 0$, т.к. совпадение всей строки со своей же нулевой позицией тривиально и не несёт полезной информации для сдвигов.

==Опр.== **Z-блок** - отрезок подстроки $[l, r] = [l, l + z[l] - 1]$, совпадающий с префиксом строки $S[:r-l+1]$ для некоторого $l < i$, т.ч. $z[l] > 0$.

> [!INFO] Геометрический смысл
> Каждое ненулевое значение $z[i]$ задаёт окно ширины $z[i]$, накладываемое на строку начиная с индекса $i$, которое полностью идентично префиксу строки $S[:z[i]]$. Z-блок $[l, r]$ - это "самое правое" такое окно, достигнутое алгоритмом к текущему шагу.

> [!TIP] Интуиция ускорения через Z-блок
> Представьте, что вы сканируете строку слева направо и зафиксировали отрезок $[l, r]$, который заведомо равен префиксу строки $S[:r-l+1]$. Когда вы переходите к позиции $i \in [l, r]$, вам не нужно сравнивать символы с нуля. Позиция $i$ внутри отрезка соответствует позиции $i - l$ в самом начале строки. Значение $z[i - l]$ уже вычислено! 
> - Если совпадение внутри блока не доходит до его правой границы $r$, то $z[i]$ точно равно $z[i - l]$.
> - Если совпадение доходит до границы $r$ или выходит за неё, мы точно знаем, что первые $(r - i + 1)$ символов совпадают, и можем допроверять символы наивно только за пределами правой границы $r$, продвигая её ещё дальше вправо.

## Алгоритм построения Z-функции

> [!important] Цель
> Построение массива Z-функции $z$ длины $n$ для заданной строки $S = s_0 s_1 \dots s_{n-1}$.

### 1. Наивный алгоритм
#### Алгоритм

1) Создать массив $z$ длины $n$, заполнив его нулями: $z[0] = 0$.
2) Для каждого индекса $i$ от $1$ до $n-1$:
	2.1) Инициализировать счётчик совпадений $k = 0$.
	2.2) Пока $i + k < n$ и $S[k] == S[i + k]$, увеличивать $k = k + 1$.
	2.3) Записать полученное значение: $z[i] = k$.
3) Вернуть заполненный массив $z$.

#### Асимптотика

- **Временная сложность:** Внешний цикл по $i$ выполняется $n-1$ раз. Для каждого $i$ внутренний цикл по $k$ в худшем случае (например, для строки из одинаковых символов $S = \text{"aaaa..."}$) делает $n-i$ итераций. Суммарная временная сложность составляет:
  $$T(n) = \sum\limits_{i=1}^{n-1} (n - i) = \frac{n(n-1)}{2} = O(n^2)$$

- **Пространственная сложность:** Дополнительная память составляет $O(1)$ без учёта результирующего массива $z$ размера $O(n)$.

#### Корректность

По определению Z-функции $z[i] = \max\limits_{k \in \overline{0, n-i}} \{ k \mid S[:k] = S[i:i+k] \}$. Наивный алгоритм проверяет равенство символов $S[k] == S[i+k]$ начиная с $k = 0$ последовательно для каждого $k$. Алгоритм останавливается на первом индексе $k$, для которого $S[k] \neq S[i+k]$ (или при достижении конца строки $i+k = n$). Следовательно, найденное значение $k$ строго является максимальным количеством подряд идущих совпадающих символов, что гарантирует точное соответствие определению $z[i]$.

#### Пример применения

Пусть $S = \text{"abacaba"}$, $n = 7$.
- $i = 0$: по соглашению $z[0] = 0$.
- $i = 1$ ($S[1:] = \text{"bacaba"}$): $S[0] = \text{'a'} \neq S[1] = \text{'b'} \implies z[1] = 0$.
- $i = 2$ ($S[2:] = \text{"acaba"}$): $S[0] = \text{'a'} == S[2] = \text{'a'}$, но $S[1] = \text{'b'} \neq S[3] = \text{'c'} \implies z[2] = 1$.
- $i = 3$ ($S[3:] = \text{"caba"}$): $S[0] = \text{'a'} \neq S[3] = \text{'c'} \implies z[3] = 0$.
- $i = 4$ ($S[4:] = \text{"aba"}$): $S[0..2] == S[4..6] = \text{"aba"} \implies z[4] = 3$.
- $i = 5$ ($S[5:] = \text{"ba"}$): $S[0] = \text{'a'} \neq S[5] = \text{'b'} \implies z[5] = 0$.
- $i = 6$ ($S[6:] = \text{"a"}$): $S[0] == S[6] = \text{'a'} \implies z[6] = 1$.
- Итоговый массив: $z = [0, 0, 1, 0, 3, 0, 1]$.

### 2. Линейный алгоритм
#### Алгоритм

1) Инициализировать массив $z$ длины $n$ нулями: $z[0] = 0$.
2) Инициализировать границы правейшего Z-блока: $l = 0$, $r = 0$.
3) Для каждого $i$ от $1$ до $n-1$:
	3.1) **Использование ранее посчитанного контекста:** Если $i \le r$, положить начальное значение $z[i] = \min(r - i + 1, z[i - l])$. Иначе ($i > r$) положить $z[i] = 0$.
	3.2) **Наивное наигрывание совпадений:** Пока $i + z[i] < n$ и $S[z[i]] == S[i + z[i]]$, инкрементировать $z[i] = z[i] + 1$.
	3.3) **Обновление правейшего Z-блока:** Если $i + z[i] - 1 > r$, обновить границы Z-блока: $l = i$, $r = i + z[i] - 1$.
4) Вернуть массив $z$.

```python
def z_function(s: str) -> list[int]:
    n = len(s)
    z = [0] * n
    l, r = 0, 0
    for i in range(1, n):
        if i <= r:
            z[i] = min(r - i + 1, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] - 1 > r:
            l = i
            r = i + z[i] - 1
    return z
```

#### Асимптотика

- **Временная сложность:**
  Проанализируем количество проверок в цикле `while` (шаг 3.2):
	  1. Каждая итерация цикла `while` либо завершается неудачей на первом же сравнении (что происходит не более $1$ раза за каждый шаг внешнего цикла $i$), либо увеличивает значение $z[i]$ хотя бы на $1$.
	  2. Увеличение $z[i]$ приводит к сдвигу правой границы Z-блока $r = i + z[i] - 1$ строго вправо.
	  3. Поскольку граница $r$ монотонно возрастает от $0$ до $n-1$, успешных итераций цикла `while`, продвигающих $r$, за весь прогон алгоритма может быть не более $n$.
	  4. Следовательно, суммарное число проверок символов во внутреннем цикле не превосходит $2n$. Время работы алгоритма строго $O(n)$.

- **Пространственная сложность:** Память под результирующий массив $z$ составляет $O(n)$, дополнительная память для хранения границ $l, r$ - $O(1)$.

#### Корректность

Доказательство проводится индукцией по индексу $i$.
- **База ($i = 0$):** По соглашению $z[0] = 0$. Границы $l = 0, r = 0$ корректны.
- **Предположение:** Пусть для $\forall j < i$ значения $z[j]$ и границы правейшего Z-блока $[l, r]$ рассчитаны верно.
- **Шаг:** Докажем корректность вычисления $z[i]$.
	1. *Случай $i > r$:* Символы строки в позиции $i$ и далее ещё не входили ни в один из ранее рассмотренных Z-блоков. Отсутствие информации обязывает алгоритм положить $z[i] = 0$ и запустить наивное посимвольное сравнение с $S[:n-i]$, что заведомо верно по определению.
	2. *Случай $i \le r$:* По определению Z-блока $[l, r]$ подстрока $S[l:r+1]$ совпадает с префиксом $S[:r-l+1]$. Следовательно, подстрока $S[i:r+1]$ совпадает с подстрокой $S[i-l : r-l+1]$.
		- *Подслучай 2.1: ($z[i-l] < r - i + 1$):* Совпадение префикса для позиции $i-l$ заканчивается строго внутри блока $[l, r]$. Из равенства подстрок следует: $S[i : i + z[i-l]] = S[i-l : i-l + z[i-l]] = S[:z[i-l]]$, а следующий символ $S[i + z[i-l]] \neq S[z[i-l]]$. Значит, $z[i] = z[i-l]$ точно, и дальнейшие проверки не нужны (цикл `while` завершится на первой итерации).
		- *Подслучай 2.2: ($z[i-l] \ge r - i + 1$):* Совпадение префикса распространяется до границы $r$ или за неё. Мы гарантируем совпадение первых $r - i + 1$ символов: $S[i : r+1] = S[:r-i+1]$. Символы левее $r+1$ неизвестны, поэтому алгоритм начинает наивную проверку строго с позиции $r+1$, постепенно увеличивая $z[i]$.
	3. *Обновление $[l, r]$:* Если после наивной проверки $i + z[i] - 1 > r$, то найден более правый Z-блок. Присвоение $l = i, r = i + z[i] - 1$ сохраняет инвариант алгоритма. Индукционный шаг доказан.

#### Пример применения

Пусть $S = \text{"aabaa"}$, $n = 5$.
- $i = 0$: $z[0] = 0, l = 0, r = 0$.
- $i = 1$ ($S[1] = \text{'a'}$):
	- $i > r \implies z[1] = 0$.
	- `while`: $S[0] == S[1]$ ('a' == 'a') $\implies z[1] = 1$. $S[1] \neq S[2]$ ('a' $\neq$ 'b').
	- $1 + z[1] - 1 = 1 > r(0) \implies l = 1, r = 1$.
- $i = 2$ ($S[2] = \text{'b'}$):
	- $i > r(1) \implies z[2] = 0$.
	- `while`: $S[0] \neq S[2]$ ('a' $\neq$ 'b') $\implies z[2] = 0$.
	- Границы $[l, r]$ не обновляются ($l = 1, r = 1$).
- $i = 3$ ($S[3] = \text{'a'}$):
	- $i > r(1) \implies z[3] = 0$.
	- `while`: $S[0..1] == S[3..4] = \text{"aa"} \implies z[3] = 2$.
	- $3 + z[3] - 1 = 4 > r(1) \implies l = 3, r = 4$.
- $i = 4$ ($S[4] = \text{'a'}$):
	- $i \le r(4) \implies z[4] = \min(4 - 4 + 1, z[4 - 3]) = \min(1, z[1]) = \min(1, 1) = 1$.
	- `while`: $i + z[4] = 5 = n \implies$ конец строки.
	- $4 + 1 - 1 = 4 \le r(4) \implies$ границы без изменений.
- Итоговый массив: $z = [0, 1, 0, 2, 1]$.
