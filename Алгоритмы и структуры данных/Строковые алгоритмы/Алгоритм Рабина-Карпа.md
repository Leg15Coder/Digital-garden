### Цель и проблематизация

Прямое посимвольное сравнение двух строк длины $L$ требует $O(L)$ операций. В задачах, где требуется совершать многочисленные сравнения подстрок (например, поиск паттерна в тексте, поиск наибольшей общей подстроки, подсчёт количества различных подстрок), наивные алгоритмы приводят к квадратичной или кубической временной сложности $O(n \cdot m)$ или $O(n^3)$.

Идея полиномиального хеширования заключается в отображении произвольной строки $S$ в элемент ограниченного числового поля $\mathbb{Z}_m$. Это позволяет сравнивать подстроки за $O(1)$ в среднем после однократного препроцессинга за $O(n)$, сводя проверку равенства строк к сравнению двух целых чисел.

## Алгоритм Рабина-Карпа

> [!important] Цель
> 
> Поиск всех точных вхождений образца (паттерна) $P$ длины $m$ в текст $T$ длины $n$ путём сопоставления их полиномиальных хешей.
> 
>   

### 1. Алгоритм

1. Если $m > n$, вернуть пустой список.
2. Вычислить хеш образца $h_P = h(P)$ и предрасчитать префиксные хеши $H_T$ и степени $P_T$ для текста $T$.
3. Инициализировать список результатов $\text{occurrences} = []$.
4. Для каждого индекса $i$ от $0$ до $n - m$: 4.1) Вычислить хеш текущей подстроки текста $h_{sub} = h(T[i : i+m])$. 4.2) Если $h_{sub} == h_P$: - _(По желанию)_ Посимвольно проверить равенство $T[i : i+m] == P$ для исключения коллизии. - Добавить индекс $i$ в $\text{occurrences}$.
5. Вернуть $\text{occurrences}$.

```Python
def rabin_karp_search(pattern: str, text: str, x: int = 31, m: int = 10**9 + 7) -> list[int]:
    n, len_p = len(text), len(pattern)
    if len_p > n:
        return []
    
    # Хеш шаблона
    h_p = 0
    for char in pattern:
        code = ord(char) - ord('a') + 1
        h_p = (h_p * x + code) % m
        
    # Префиксные хеши текста
    ht = [0] * (n + 1)
    p = [1] * (n + 1)
    for i in range(n):
        code = ord(text[i]) - ord('a') + 1
        ht[i + 1] = (ht[i] * x + code) % m
        p[i + 1] = (p[i] * x) % m
        
    occurrences = []
    for i in range(n - len_p + 1):
        # Получаем хеш окно длины len_p за O(1)
        cur_h = (ht[i + len_p] - ht[i] * p[len_p]) % m
        cur_h = (cur_h + m) % m
        
        if cur_h == h_p:
            # Опциональная посимвольная проверка (для защиты от коллизий):
            if text[i:i + len_p] == pattern:
                occurrences.append(i)
                
    return occurrences
```

### 2. Асимптотика

- **Временная сложность:**
    - _Без посимвольной допроверки (вероятностная):_ $O(n + m)$ детерминированно.
    - _С посимвольной допроверкой:_
        - В среднем (ожидаемое время): $O(n + m)$, если вероятность коллизии мала.
        - В худшем случае: $O(n \cdot m)$, если хеш-функция постоянно даёт коллизии.
- **Пространственная сложность:** $O(n)$ для хранения префиксных хешей текста $T$.

### 3. Корректность

#### Лемма _(О вероятности коллизии по лемме Шварца-Зиппеля)_

Пусть $P \neq T[i:i+m]$ - две различные строки длины $m$. Вероятность коллизии $\mathbb{P}(h(P) = h(T[i:i+m]))$ при случайном выборе основания $x \in \mathbb{Z}_m^*$ не превосходит $\frac{m-1}{m}$.

#### Доказательство

1. Равенство хешей $h(P) = h(T[i:i+m])$ равносильно выполнению равенства:$$\sum\limits_{j=0}^{m-1} (P[j] - T[i+j]) \cdot x^{m-1-j} \equiv 0 \pmod m$$
2. Обозначим $Q(x) = \sum\limits_{j=0}^{m-1} d_j \cdot x^{m-1-j}$, где $d_j = P[j] - T[i+j]$. Поскольку $P \neq T[i:i+m]$, существует хотя бы один ненулевой коэффициент $d_j \neq 0$, следовательно, $Q(x)$ - ненулевой многочлен степени не выше $m - 1$ над полем $\mathbb{Z}_m$.

3. По основной теореме алгебры ненулевой многочлен степени $d \le m - 1$ над полем $\mathbb{Z}_m$ имеет не более $m - 1$ корней.

4. Следовательно, из $m$ возможных выборов случайного основания $x$ коллизию могут дать не более $m - 1$ значений:$$\mathbb{P}(Q(x) \equiv 0 \pmod m) \le \frac{m - 1}{m}$$При $m \approx 10^9$ вероятность коллизии для одного сравнения составляет $\approx 10^{-9}$. $\blacksquare$

### Пример применения

Пусть $P = \text{"aba"}$ ($m = 3$), $T = \text{"ababa"}$ ($n = 5$). $x = 3$, $m = 1009$.
1. Хеш образца $P = \text{"aba"}$: $h_P = 16$.
2. Массив префиксов текста $T$: $H_T = [0, 1, 5, 16, 50, 151]$, $P[3] = 27$.
3. Сдвиг $i = 0$ ($T[0:3] = \text{"aba"}$):$$h(T[0:3]) = (H_T[3] - H_T[0] \cdot P[3]) \bmod 1009 = 16 == h_P \implies \text{Вхождение на позиции } 0.$$
4. Сдвиг $i = 1$ ($T[1:4] = \text{"bab"}$):$$h(T[1:4]) = (H_T[4] - H_T[1] \cdot P[3]) \bmod 1009 = (50 - 1 \cdot 27) \bmod 1009 = 23 \neq 16.$$
5. Сдвиг $i = 2$ ($T[2:5] = \text{"aba"}$):$$h(T[2:5]) = (H_T[5] - H_T[2] \cdot P[3]) \bmod 1009 = (151 - 5 \cdot 27) \bmod 1009 = (151 - 135) \bmod 1009 = 16 == h_P$$
    $\implies \text{Вхождение на позиции } 2.$ Результат: `[0, 2]`.

### +ы & -ы

> [!SUCCESS] Достоинства
> 
>   
> 
> - Простота реализации и универсальность для сопоставления подстрок произвольной длины за $O(1)$.
>     
>       
>     
> - Легко обобщается на задачу поиска множества шаблонов одинаковой длины (помещением хешей всех шаблонов в хэш-сет).
>     
>       
>     
> - Позволяет легко реализовывать двумерный поиск паттерна в матрицах.
>     
>       
>     

> [!FAILURE] Недостатки
> 
>   
> 
> - Вероятностная природа: риск получить коллизию (False Positive) при неудачном подборе модуля и основания.
>     
>       
>     
> - Уязвимость к Anti-Hash тестам, если модуль $m$ и основание $x$ фиксированы зараннее и известны противнику.
>     
>       
>     

> [!WARNING] Техника двойного хеширования (Double Hashing)
> 
> Для снижения вероятности коллизий до минимума ($\approx 10^{-18}$) на практике используют парное хеширование по двум независимым простым модулям $m_1$ и $m_2$ (например, $m_1 = 10^9 + 7, m_2 = 10^9 + 9$). Сравнение хешей в таком случае проводится как сравнение пар целых чисел $(h_1, h_2)$.
